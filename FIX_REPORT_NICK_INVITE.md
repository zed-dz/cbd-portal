# Fix Report — Worker Invite Flow

**Incident:** Nick Gimbert (worker invited to the JK Williams site) accepted his invite email but landed on `http://localhost:3000` instead of the live portal. He couldn't get past the broken redirect.

**Status:** RESOLVED — 12 June 2026.

**Resolution scope:** Both CBD Portal and MRA Portal (mirrored fix).

---

## Root cause

Supabase Auth's built-in invite/confirmation/password-reset emails use the project's **Site URL** setting as the redirect base. Both Supabase projects (CBD and MRA) still had `Site URL = http://localhost:3000` — the default from initial dev setup, never updated when production went live.

When someone (admin or anyone with Supabase Dashboard access) invited Nick via **Authentication → Users → Invite User**, Supabase generated the link as `http://localhost:3000/?code=...` instead of `https://cbd-portal-gray.vercel.app/?code=...`. Nick clicked it, his browser tried to reach localhost on his phone, got the "Safari can't open the page" error.

The custom in-app invite flow (`Workers → + Add Worker → Send Invite`) was unaffected because it uses our own `send-invite` edge function with a hard-coded `PORTAL_URL` env var. But there were three lurking issues:

1. The "Copy onboarding link" buttons used `window.location.origin` — so an admin testing on `localhost:3000` would copy and share a localhost URL.
2. The signup confirmation email had no `emailRedirectTo` set, so it also fell back to Site URL.
3. There was no backup path if email delivery failed. Some workers' mailservers reject Resend's sandbox sender; some workers simply don't check email.

## How to use the new backup invite options

When you open **Pending Workers** (or any worker's edit modal), each worker now shows four invite buttons:

| Button | When to use it |
|---|---|
| ✉️ **Send Email** | Default. Goes via Gmail if connected, else Resend. Best for office-based workers. |
| 💬 **WhatsApp** | Opens WhatsApp on your phone/desktop with worker's number + invite message pre-filled. Best for site-based workers who answer WhatsApp instantly. |
| 📨 **SMS** | Opens your phone's Messages app with worker's number + invite message pre-filled. Backup for workers without WhatsApp. |
| 🔗 **Copy** | Copies just the onboard URL to your clipboard. For ad-hoc sharing (Teams, Slack, Telegram, etc.). |

All four buttons share the **same underlying URL** generated by the same logic, so there's no chance of one path working and another being broken.

## What this DOESN'T fix

These are out of scope for this incident but worth noting:

- **Resend sandbox limitation.** Resend's default sender (`onboarding@resend.dev`) only delivers to your own Resend account email until you verify a domain. To send invite emails to *anyone*, verify `cbdplantandlabour.com.au` (or whichever domain you own) in your Resend dashboard, then set the `INVITE_FROM` edge function env var.
- **Gmail OAuth setup.** If Gmail is connected via the Inbox page, invite emails go through your Gmail account and look more personal than Resend. Worth doing if you haven't already.
- **Multiple admins inviting via Dashboard.** Anyone with Supabase Dashboard access can invite users from `Authentication → Users → Invite User`. That now sends working links (Site URL is fixed), but it bypasses the in-app `workers` row creation — preferred flow is still `Workers → + Add Worker` so the worker gets a profile_token and onboard URL.
